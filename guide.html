使用前准备

Agent OS 是工作流和运行时管理器，不提供 Claude、Codex 等模型服务本身。开始前请准备至少一个可正常运行的 Agent CLI。

AGENT CLI

安装并登录 CLI

可在 Agent OS 设置中查看、安装、升级和诊断受支持的 CLI；厂商账号授权、订阅与登录仍由对应 CLI 完成。

WORKSPACE

准备工作目录

会话和任务会在你选择的真实目录中运行。代码项目建议先确认 Git 状态，并明确 Agent 的权限模式。

本地优先不等于模型请求永不出机：会话、任务和索引默认保存在本机，但提示词和文件是否发送到外部服务取决于你使用的 CLI、模型和权限配置。

首次启动

01

自动发现 CLI

引导页扫描 PATH 与常见安装位置，显示已安装、缺失和异常状态。完成引导后进入工作台。

02

检查设置

打开设置 → CLI 管理，按需执行重新扫描、安装、升级或诊断；远程节点、语言、主题和诊断也在设置中管理。

03

确认 CLI 可用

在终端运行对应 CLI 并完成厂商登录。Agent OS 能启动和管理 CLI，但不会绕过工具本身的授权流程。

创建会话或原生 CLI

左侧第一个入口支持“会话”和“CLI”两种模式，共用 Runtime Host、Agent、模型和工作目录选择。

SESSION

结构化会话

  • 消息与工具事件以对话形式展示。
  • 运行中继续输入会进入持久队列，不覆盖当前回合。
  • 可从历史、搜索结果或任务运行记录重新打开。
CLI / PTY

原生终端

  • 使用原生 PTY 与 xterm 交互。
  • 适合需要完整 ANSI 输出和直接键盘控制的场景。
  • 关闭窗口后，受 Runtime daemon 管理的后台能力不依赖渲染窗口。

任务看板与定时执行

任务保存工作意图、执行者、运行位置、工作目录、计划和审阅状态；每次运行关联一个真实会话。

01

创建任务

在看板点击“新建任务”，填写标题与提示词，并选择 Runtime Host、Agent CLI、模型、工作目录、权限和会话策略。

02

运行或计划

可仅创建、创建并运行，或配置一次性时间点/Cron、IANA 时区和错过执行策略。暂停、恢复和立即运行都在定时页完成。

03

审阅结果

任务执行时进入 In Progress，成功或失败后进入 Review。打开关联会话检查结果，再由人工确认 Done。

同一工作目录的计划任务会串行执行。计划由目标 Runtime daemon 持有；关闭桌面窗口后，本机或远程节点仍可按计划触发。

对比、记忆、Web 与统计

COMPARE

多面板对比

并排添加 Web、结构化会话或 CLI 面板，单独发送或批量发送同一问题。

MEMORY

历史与记忆

搜索支持来源的会话并跳回上下文；分别管理会话、经验、候选和记忆策略。

WEB

通过书签打开常用站点并保留站点会话，可把 Web 页面加入对比工作流。

STATS

统计与成长

查看会话、消息、Token、活跃趋势、项目与模型使用情况，并浏览成长 Cardex。

接入远程 Runtime 节点

远程节点适合把 Agent 运行在局域网中的另一台机器。节点主动连接主控，接入后可成为会话和任务的 Runtime Host。

01

生成接入信息

在设置 → 远程节点中创建接入信息。接入凭据为敏感信息，不要发布到聊天、日志或代码仓库。

02

安装节点包

从 v0.2.8 Release 选择 macOS arm64、Linux arm64/x64 或 Windows x64 bootstrap 节点包，也可使用 install-node.sh。

03

检查并使用

节点上线后检查 Agent 发现状态和目录访问，再在新建会话或任务时选择该 Runtime Host。

常见问题

为什么 Agent OS 没有自动登录 Claude/Codex？

Agent OS 只负责发现、启动和管理 CLI。厂商账号、订阅、OAuth 或 API Key 授权必须按对应 CLI 的官方流程完成。

macOS 提示无法验证开发者怎么办？

当前 DMG 未做 Apple Developer ID 公证。请在 Finder 中右键 Agent OS 选择“打开”，确认后系统会记住选择。

数据是不是完全不会离开电脑？

会话元数据、任务、索引和统计默认保存在本机；但模型请求是否发送到外部服务由所选 CLI、模型服务商和权限配置决定。

在哪里查看版本更新？

应用会检查 agent-life GitHub Release。也可查看 更新日志 或直接下载最新制品。
